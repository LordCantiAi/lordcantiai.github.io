MuppetLabs Hybrid Execution, Cost Optimization & Quality Gate Architecture

Executive Summary

This architecture pairs a cloud-hosted frontier model (Gemini 3.7 Flash, Claude 4.6 Haiku) as the primary orchestrator with a fleet of local, zero-cost specialized lab models (MuppetLabs LLMs) on Apple Silicon / local compute. By enforcing Prefix-Cache Preservation, 65K Context Auto-Compaction (6.5%), Zero-Polling Asynchronous Delegation, and a Statler-Canti Maker-Checker Quality Loop, per-turn cloud costs drop from $0.11+ down to ~$0.005 while eliminating code and UI defects.

Crucially, offloading heavy tasks to asynchronous subagents unlocks continuous conversational flow: users are never trapped waiting for long execution, test runs, or compilation loops (eliminating the classic "need to interrupt Claude but stuck waiting" UX barrier).

The Three Financial Pillars:

A. Protecting Frontier Prefix Caching (75–80% Discount)

  • Frontier models (Gemini 3.7 Flash) automatically cache prompt prefixes $\ge$ 32k tokens.
  • When previous turns remain append-only and static, cached prefix tokens cost 75% less.
  • The Danger of Inline Tool Output Bloat: Printing 5,000-line build logs or giant JSON dumps directly into the root agent context pollutes the prompt for every future turn, accumulating compounding token drag.
  • The Solution: Execute heavy builds and searches in local subagents (Statler/Kermit); only compact status messages return to the root prompt.

B. The 65K Token Compaction Gate & 6.5% Daemon Threshold Caveat

  • While Gemini supports a 1M token window, running beyond 65k–85k tokens steadily inflates cost and triggers Google AI Studio 429 (Resource Exhausted - TPM Limit) errors during rapid exchanges.
  • Configuration Caveat: By default, generic agent daemons evaluate auto-compaction thresholds relative to total context window size (contextWindow - reserveTokens $pprox$ 98% of 1M tokens), leaving large-context models at risk of silent token creep and cold-read cache TTL expirations ($0.07+/turn on cache misses).
  • Fix & Tune: Configure compaction.thresholdRatio: 0.065 (6.5% of the 1M window $pprox$ 65k tokens) in ~/.prime/agent/settings.json and enforce shouldCompact() at $\le$ 6.5% context capacity to automatically reset context to ~23k–39k tokens, maintaining high speed, zero rate limits, and per-turn costs under $0.005.

C. Zero-Polling Asynchronous Dispatch & Continuous Conversational Flow

  • Anti-Pattern: Root agent executing busy-wait loops (time.sleep or polling agent_observe) burns multiple cloud API calls just waiting for a child to complete, while locking the user out of the conversation.
  • The Policy: Root agent dispatches the subagent with await rlm(...) and immediately ends its turn. The child notifies the parent asynchronously via agent_message.send, cutting parent roundtrips by >80%.
  • Human-in-the-Loop UX Advantage: If you've ever felt the urge to interrupt an AI agent while it was stuck executing a multi-minute build, test suite, or file crawl, this architecture resolves that latency lockup. Because time-consuming work runs strictly out-of-band in dedicated local subagents, the primary conversational thread remains nimble, responsive, and immediately open for new user steering, quick questions, or course corrections.

5. Implementation Blueprint: How to Deploy This Architecture

If you want to implement this hybrid zero-cost execution and quality architecture yourself, ensure the following core components and configurations are in place:

1. Cloud Orchestrator Plane (The "Thinker")

  • Smallest Cost-Optimized Frontier Reasoning Models: Deploy a lightweight, fast reasoning model configured with low thinking effort and prompt prefix caching:
  • Gemini 3.7 Flash (Low Thinking): Massive 1M context with automatic prefix cache discounts (>75% savings for $\ge$ 32k prompts) and ultra-fast turn latency.
  • Claude 4.6 Haiku: Lightweight, highly capable frontier reasoning model offering minimal token costs with prompt caching support.
  • Luna / Small Reasoning Models (Low Effort): Fast distilled reasoning engines tuned on low thinking effort for rapid orchestration and planning without high token generation overhead.
  • Agent Harness with Subagent RPC: Use an agent runtime (such as Prime Agent) capable of spawning isolated child agents (rlm) and communicating via structured, non-blocking asynchronous messages (agent_message).

2. Local Inference Mesh (The "Workers" & "Auditors")

  • Local GPU / Apple Silicon Compute: Set up local model servers (llama.cpp, vLLM, or Ollama) running on your local network.
  • Tiered Role Assignment:
  • The Builder (Coding Model): 27B–35B parameter model (e.g., Qwen 2.5 Coder 32B) for writing code, building binaries, and running unit test suites.
  • The Finder (Fast Classifier): Lightweight 8B–20B model (e.g., GPT-OSS-20B / Gemma) for quick grep, file lookups, and data formatting.
  • The Gatekeeper (Deep Auditor): Large local model (e.g., 120B MoE or 70B dense) for architectural audits, DOM/lifecycle verification, and UX compliance.

3. Context & Cost Governance Configuration

  • 6.5% Context Compaction Threshold: Configure your agent runtime (e.g., in settings.json under compaction.thresholdRatio: 0.065) to trigger auto-compaction before context bloat incurs cache-miss penalties ($0.07+/turn) or triggers provider TPM rate limits.
  • Zero-Polling Asynchronous Protocol: Enforce a strict non-blocking rule—root orchestrators must dispatch work to subagents and immediately yield their turn rather than executing polling loops (time.sleep).

4. Dual-Agent Maker-Checker Quality Pipeline

  • Separation of Concerns: Never permit the code-generating model to perform its own final approval.
  • Automated Quality Checks: Chain every code change through:
    1. Statler: Syntactic generation + compilation (cargo test, npm test).
    2. Canti: Diff review against repository AGENTS.md conventions, DOM/HTMX lifecycle validation, and Dan Smith BASIC UX usability audits.
