⚙️ Cache-Stable Continual Harness — Cross-Provider Findings

Companion report to the prime-agent implement/v4-cache-stable-harness work. Empirical cache measurements against three real providers. 2026-09-08.

The objective: On new turns that change harness state, cache hits should climb, and the whole prompt must not be reprocessed just because a state line changed. We hypothesized byte-stable head + append-only tail is the right shape across providers. This report tests that on Canti (local Qwen), DeepSeek, and Google Gemini 3.7 Flash.

Why plan-v4 delivers this

Prime Agent's Continual Harness (agent memories, skills, notes) used to be inlined into the immutable system prompt and rebuilt on each turn. Any change shifted the leading bytes → every provider cache keyed on that shifting prefix missed → the header is re-billed on each call. Under cache-stable (plan v4):

  • Harness state is NOT in the system prompt (head stays byte-stable).
  • Full state snapshot only at cold boundaries (session start, post-compaction).
  • Live changes reach the model as APPENDED tail deltas ([harness] kind "id" = value); prior bytes are never rewritten.
  • Result: the served prefix is immutable; cache can hold it; each turn only appends the genuinely new tail.

Reading: DeepSeek caches the stable lead (~128) but treats each newly-grown body as a first-send miss. In an ever-growing append-forward conversation, only the stable head reuses cache; new tails miss once. This is why the earlier 150M-token burn happened under a churning head — and why a stable head (plan-v4) still helps, but DeepSeek is the least economic under pure linear growth.

Balance impact: a full multi-turn probe (~380 tokens) left the balance unchanged at $9.29 — $\sim$0.00. "Using the balance" is negligible at realistic probe/tool scale regardless of cache behavior.

Bottom line: The cache-stable design (byte-stable immutable head + append-only state deltas / snapshots only at cold boundaries) is validated on all three providers. State changes never force a full prompt reprocess. DeepSeek's economic sweet spot is stable-head reuse + retries (not pure linear tail growth); Gemini's explicit cached-content gives the strongest guarantee (a large fixed cached block, only deltas billed). Local-host Canti caching is free and behaves ideally.
